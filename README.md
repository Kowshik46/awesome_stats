# Site stats dashboard

Private admin dashboard for kowshik.co.in visitor stats. A small zero-dependency Node service reads Supabase (`page_views`, `page_events`) with a service key kept only in server env vars, aggregates in IST, and serves a password-protected dark UI. `/test` rows are excluded.

## Env vars (set in Render, never committed)
| Name | Value |
|---|---|
| `SUPABASE_URL` | `https://mytaeovzlriyrqnydaas.supabase.co` |
| `SUPABASE_SERVICE_KEY` | Supabase → Project Settings → API → `service_role` key |
| `ADMIN_PASSWORD` | the password you log in with |
| `SESSION_SECRET` | auto-generated by `render.yaml` |

## Deploy on Render
1. Render → New → Blueprint → pick this repo (reads `render.yaml`).
2. Fill the three prompted env vars (`SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `ADMIN_PASSWORD`); `SESSION_SECRET` is generated.
3. Open the service URL and log in.

## Local
`cp .env.example .env`, export the vars, `node server.js`. Tests: `node test.js`.

Free Render services sleep after inactivity, so the first load can take ~30s.

## Visitor ID (branch `visitor-id`)
Counts people, not IPs. Go-live order: run `supabase/migration.sql`, deploy `supabase/ping/index.ts` as the `ping` Edge Function, merge the site change, then merge this branch. Older rows fall back to `ip_hash`.

## Reports
`/reports` lists the "Report a broken step" submissions from the article pages (table `step_reports`, written by the `note` Edge Function). Mark each new, fixed or wont fix. Uses the existing service key; no new env vars.
